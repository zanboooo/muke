## ⛔ 动手前先读这一段

**这是一个 public 仓库。`data/` 下的每一个文件，任何人都能直接下载。**
不是「不显眼」，是「公开」。往里放东西之前先问一句：这条信息见报了会怎样。

| 红线 | 为什么 |
|---|---|
| **不要把个人数据放进 `data/`** | 姓名、电话、身份证、住址、薪资、证件照一概不行。经纪人／星探姓名是例外——候选人链接必须能匿名解析，这是设计如此 |
| **不要手工往 `data/` 放文件** | 那个目录整个由 `tools/sync-portal.js` 生成。手放的东西会被下一次同步的孤儿清扫删掉，或者更糟：躲过清扫一直留着 |
| **不要在公开产物里多输出一个字段** | `tools/checks.js` 的字段契约是双向的：缺前端要读的字段会红，多输出前端不读的字段也会红 |
| **不要加 LICENSE** | 加了等于邀请别人 fork。fork 会永久留存历史副本，我们清不掉 |
| **不要加分支保护** | `sync-portal` 每天 8 次用 `github-actions[bot]` 往 `main` 推 `data/`。任何保护规则都会把它拦死，而症状是「同步全绿但数据不更新」 |
| **只放报名链路的东西** | 内部规程页、演示页、员工向页面都在 [`MSOP`](https://github.com/zanboooo/MSOP) 仓库。这里只留候选人会看到的 |

**删文件删不掉历史。** `git rm` 只加一个删除提交，文件仍在之前每一个提交的树里，
GitHub 会一直按 SHA 提供它。这个仓库 2026-09-06 正因为这件事重建过一次——
现在它只有一个提交，历史里没有任何东西可挖。请保持这个性质。

## 这个站是怎么跑起来的

```
Lark 多维表格 (Base2_HR-Ops)
      │  tools/sync-portal.js 每天 8 次拉数据、跑护栏、生成产物
      ▼
   data/*.json ──→ GitHub Pages ──→ 候选人打开 join/?a=<经纪人>
      │                                    │
      │                                    ▼
      └─ 归因码写进链接 ────────→ Lark 报名表单（提交后跳回本站标记完成）
```

产物都在 `data/`，除一个例外全部由同步脚本生成：

| 文件 | 内容 | 谁读 |
|---|---|---|
| `jobs.json` | 在招岗位、JD、表单链接 | `join/` |
| `manual.json` | **手动维护**：在职人数写「65+」、入职周期、每岗位职级阶梯 | `join/` |
| `bench.json` | 全局基准比率（只放比率，不放绝对数） | `agent/` |
| `j/<经纪人>.json` | 归因码解析 | `join/?a=` |
| `s/<星探码>.json` | 归因码解析 | `join/?s=` |
| `p/<星探码>.json` | 星探业绩面板，**AES-256-GCM 加密** | `agent/` |
| `_status.json` | 运营看板，**加密**，需 `STATUS_PIN` | `status/` |

## 和 MSOP 的分工

内部规程图形载体（权限矩阵、考勤、笔试、入职、头像台等 19 个页面）2026-09-06 拆到了
[`MSOP`](https://github.com/zanboooo/MSOP)。**因为这个仓库的网址印在对外招聘物料上**——
任何人顺着报名页就能摸到仓库根目录，不该让他一并翻到内部规程。

旧地址由 `404.html` 兜底转发到 MSOP，路径 / query / hash 原样带走
（入职私信里的 `welcome/#p=...` 带着人员信息，必须保留）。
**往白名单里加条目之前，先确认那个路径真在 MSOP 有。**

## 护栏

改 `tools/` 之前先读 `tools/checks.js` 和 `tools/sync-portal.js` 里的护栏段落：

- **敏感内容扫描** —— 产物里出现薪资／电话／身份证形态就中断，不提交
- **字段契约（双向）** —— 缺字段会坏前端；多字段是白扩暴露面。两个方向都拦
- **体积熔断** —— `jobs.json` 变化超阈值就停，防数据源出问题时把在招岗位清空
- **入口文件熔断** —— `j/`、`s/` 一次要删超过 3 个就只报不删
- **状态文件不降级** —— 没配 `STATUS_PIN` 时，绝不把线上的密文覆盖成明文

## 本地怎么跑

```bash
# 需要 LARK_APP_ID / LARK_APP_SECRET / LARK_BASE_TOKEN 三个环境变量
node tools/sync-portal.js      # 拉数据、跑护栏、生成 data/
node tools/check-lark.js       # 只验连通性，不写任何东西
```

⚠ 本机没有 `STATUS_PIN`（它只在 GitHub Secrets 里）。这是对的——脚本会跳过状态文件，
不会把线上那份密文覆盖成明文。

## 三条 CI

| workflow | 触发 | 做什么 |
|---|---|---|
| `sync-portal.yml` | 雅加达 10:00–17:00 每整点 ＋ 手动 | 同步数据并提交 |
| `check-lark.yml` | 手动 | 只打印计数，验凭据 |
| `weekly-report.yml` | 周一 | 发周报到 Lark 群 |

⚠ **公开仓库的 Actions 日志任何人可读。** 脚本里凡是可能打印业务内容的地方，
都加了 `if (process.env.GITHUB_ACTIONS)` 守卫，只打计数。加新日志时照这个来。
